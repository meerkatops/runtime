# Decide at the start

## Read what the project runs

- The library and version in the manifest: `parquet` and `arrow` in `Cargo.toml`; `pyarrow`, `polars` or `duckdb` in `pyproject.toml`; `@duckdb/node-api` or `@duckdb/duckdb-wasm` in `package.json`.
- A real file's footer: `parquet_metadata('<file>')` and `parquet_schema('<file>')` in DuckDB (https://duckdb.org/docs/stable/data/parquet/overview), or `pyarrow.parquet.read_metadata()` in PyArrow (https://arrow.apache.org/docs/python/parquet/parquet.html).

What a project that adopts Parquet settles before it writes its first file, so that no writer has to choose later. Each answer is a default, not a rule the pages state: the reason is beside it, and the page that supports the reason follows. Change a default when the project's readers or data say otherwise, and record the change beside the schema.

| Decision | Default | Why | Page |
|---|---|---|---|
| Fit | Confirm Parquet fits before choosing anything else | It is a file format for analytical reads, not a database | [when](when.md) |
| Rust library | The `parquet` crate with its `arrow` feature; DataFusion when the work is SQL over many files | It is the official Rust implementation; DataFusion prunes row groups and pages by default | https://docs.rs/parquet/latest/parquet/ and https://datafusion.apache.org/user-guide/configs.html |
| Python library | PyArrow to write and to control the file; Polars `scan_parquet` or DuckDB to query | PyArrow exposes every writer option and is the engine pandas uses; Polars and DuckDB push filters and projections into the scan | https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html and https://docs.pola.rs/user-guide/lazy/optimizations/ and https://duckdb.org/docs/stable/data/parquet/overview |
| TypeScript library | `@duckdb/node-api` on Node, `@duckdb/duckdb-wasm` in the browser; hyparquet only for a small read-only viewer | DuckDB is a full reader and writer with pushdown; hyparquet has no dependencies but needs an add-on for any codec beyond Snappy | https://duckdb.org/docs/stable/clients/node_neo/overview and https://duckdb.org/docs/stable/clients/wasm/overview and https://github.com/hyparam/hyparquet/blob/master/README.md |
| One writer path | One module writes every file, with every setting below passed explicitly | Writer defaults differ: uncompressed, Snappy or zstd; 65,536 to 1,048,576 rows per group | [rules](rules.md) |
| Codec | zstd, set explicitly, at the library's default level; a higher level for files written once and read many times | Good balance of compression, performance and ecosystem support; BigQuery, DuckDB, PyArrow, Polars and GDAL all read it | https://docs.rs/parquet/latest/parquet/basic/enum.Compression.html and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet and https://duckdb.org/docs/stable/guides/performance/file_formats |
| Row group size | About 120,000 rows, kept between 100,000 and 1,000,000 and above 16 MiB; 50,000 to 150,000 for spatial data | Inside the range DuckDB measures as best and at its default; BigQuery asks for at least 16 MiB; the GeoParquet guide gives the spatial range | https://duckdb.org/docs/stable/guides/performance/file_formats and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet and https://github.com/opengeospatial/geoparquet/blob/main/format-specs/distributing-geoparquet.md |
| File size | 100 MB to 1 GB per file, several row groups each | Inside DuckDB's 100 MB to 10 GB range, and under the 1 GB limit of a single BigQuery export file | https://duckdb.org/docs/stable/guides/performance/file_formats and https://cloud.google.com/bigquery/docs/exporting-data |
| Sort order | Sort rows by the column most often filtered, before writing | Tight, non-overlapping min and max per row group is what lets a reader skip | https://duckdb.org/docs/stable/data/parquet/tips |
| Statistics | On, with the page index written where the library can | Row group and page skipping depend on them; PyArrow does not write the page index unless asked | https://github.com/apache/parquet-format/blob/master/PageIndex.md and https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html |
| Dictionary | Left on | Writers fall back to plain encoding when a dictionary grows too large | https://github.com/apache/parquet-format/blob/master/Encodings.md |
| Bloom filters | Off, until a measured point lookup on a high-cardinality column needs one | They cost space, and they are off by default in the writers read | https://github.com/apache/parquet-format/blob/master/BloomFilter.md |
| Partition scheme | None until a partition would hold 100 MB; then hive `key=value` directories on one or two low-cardinality columns that queries filter on, keys always in the same order, and the key not repeated as a column in the files | Small partitions are expensive to write and read; BigQuery accepts only this layout and rejects a key that overlaps a file column | https://duckdb.org/docs/stable/data/partitioning/partitioned_writes and https://cloud.google.com/bigquery/docs/hive-partitioned-queries |
| Timestamps | `TIMESTAMP(isAdjustedToUTC=true, unit=MICROS)`: instants in UTC, microseconds; never INT96 | An instant is unambiguous; BigQuery's type table lists millis and micros but not nanos; INT96 is deprecated | https://github.com/apache/parquet-format/blob/master/LogicalTypes.md and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet |
| Local times | A wall-clock time is stored with `isAdjustedToUTC=false` and its zone in a column beside it | A local timestamp identifies no instant without a zone, and the file keeps none | https://github.com/apache/parquet-format/blob/master/LogicalTypes.md |
| Money and exact numbers | `DECIMAL` with a stated precision and scale, not a float | The type stores an exact unscaled integer; precision is required | https://github.com/apache/parquet-format/blob/master/LogicalTypes.md |
| Schema | One schema per dataset, checked in, with column order fixed; every writer casts to it and every reader names it | Readers otherwise infer the schema from the first file; BigQuery treats a different column position as a different schema | https://arrow.apache.org/docs/python/dataset.html and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet |
| Column names | Lowercase letters, digits and underscores | They pass BigQuery's column name rules, where case does not distinguish two names | https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet |
| File naming | `<prefix>/<key>=<value>/part-<uuid>.parquet`; a name is written once and never reused | An object cannot be changed in place, and a unique name keeps two writers from colliding; engines find files by the `.parquet` extension | https://duckdb.org/docs/stable/data/partitioning/partitioned_writes and https://cloud.google.com/storage/docs/objects |
| Where files live | An object storage bucket, one prefix per dataset, files written whole then listed | Objects are immutable and read-after-write consistent; a file is unreadable until its footer is written | https://cloud.google.com/storage/docs/consistency and https://parquet.apache.org/docs/file-format/data-pages/errorrecovery/ |
| Changes to data | Append by adding a file; correct by writing a replacement file and removing the old one | Files and objects are immutable | https://iceberg.apache.org/spec/ and https://cloud.google.com/storage/docs/objects |
| Table format | None while one job writes and files are only added; Iceberg or Delta Lake once writers run concurrently, rows are updated or deleted, the schema or partition layout must change, or readers need a consistent snapshot | A directory of files cannot change atomically; both formats add atomic commits over Parquet files | https://iceberg.apache.org/docs/latest/reliability/ and https://github.com/delta-io/delta/blob/master/PROTOCOL.md |
| Spatial data | GeoParquet: WKB geometry at the root of the schema, the CRS written explicitly, rows sorted spatially. Write version 1.1 metadata with a bbox covering until every reader in the pipeline reads Parquet's native geometry types, then version 2.0 | WKB is the portable encoding; GDAL writes native types only on request, and reading them needs Arrow library 20 or newer | https://geoparquet.org/releases/v1.1.0/ and https://geoparquet.org/releases/v2.0.0/ and https://gdal.org/en/stable/drivers/vector/parquet.html |
| Files from outside | Read in a sandboxed process with a memory limit; verify checksums where the writer wrote them; never pass a caller's string as the path | Sizes come from the file, and engines say malicious input can exhaust memory | https://duckdb.org/docs/stable/operations_manual/securing_duckdb/overview and https://arrow.apache.org/docs/cpp/security.html |
| Encryption | No file-level encryption unless the storage operator must not read the data; then modular encryption, with one key for footer and columns if DuckDB must read it | Modular encryption is client-side and its support varies by implementation | https://github.com/apache/parquet-format/blob/master/Encryption.md and https://duckdb.org/docs/stable/data/parquet/encryption and https://parquet.apache.org/docs/file-format/implementationstatus/ |

## Traps the pages name

- INT96 timestamps are deprecated but still written by legacy tools; readers disagree on how to read them (PyArrow as nanoseconds, DuckDB as microseconds by default). https://parquet.apache.org/docs/file-format/types/ and https://arrow.apache.org/docs/python/generated/pyarrow.parquet.read_table.html and https://duckdb.org/docs/stable/data/parquet/overview
- A timestamp written with `isAdjustedToUTC=false` is a local time, not an instant; two readers in different zones will not agree on when it happened. https://github.com/apache/parquet-format/blob/master/LogicalTypes.md
- Writing an instant drops its original time zone; only the UTC value is stored, and PyArrow gets the zone back only from the Arrow schema it embedded. https://github.com/apache/parquet-format/blob/master/LogicalTypes.md and https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html
- Nanosecond INT64 timestamps cannot hold a date before 1677 or after 2262, and BigQuery's type table does not list them. https://github.com/apache/parquet-format/blob/master/LogicalTypes.md and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet
- PyArrow raises when a timestamp cast would lose precision, and seconds always become milliseconds. https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html
- Too many small files: each costs metadata and a file open, and writing many small partitions is expensive. https://iceberg.apache.org/docs/latest/maintenance/ and https://duckdb.org/docs/stable/data/partitioning/partitioned_writes
- Too many partitions: a partition under 100 MB is below DuckDB's recommendation, and BigQuery stops at ten partition keys. https://duckdb.org/docs/stable/data/partitioning/partitioned_writes and https://cloud.google.com/bigquery/docs/hive-partitioned-queries
- Tiny row groups: 2,048-row groups ran about 3.7 times slower in DuckDB's measurement. One giant row group is the opposite trap: a single thread reads it. https://duckdb.org/docs/stable/guides/performance/file_formats
- The format's own page recommends 512 MB to 1 GB row groups and 8 KB pages, advice written for HDFS blocks; the engines' pages size by rows and default to 1 MiB pages. https://parquet.apache.org/docs/file-format/configurations/ and https://duckdb.org/docs/stable/guides/performance/file_formats
- Schema drift across files: DuckDB drops a column the first file lacks, PyArrow infers from the first file, Polars raises, and a BigQuery wildcard load fails. https://duckdb.org/docs/stable/data/multiple_files/combining_schemas and https://arrow.apache.org/docs/python/dataset.html and https://docs.pola.rs/api/python/stable/reference/api/polars.scan_parquet.html and https://cloud.google.com/bigquery/docs/loading-data-cloud-storage-parquet
- A renamed column no longer matches: DuckDB matches later files to the first by column name, while Iceberg tracks each column by a unique id. https://duckdb.org/docs/stable/data/multiple_files/combining_schemas and https://iceberg.apache.org/docs/latest/evolution/
- Dictionary blowup: a high-cardinality column outgrows its dictionary and falls back to plain encoding, so the dictionary bought nothing; reading such a column as a dictionary array saves memory only when values repeat. https://github.com/apache/parquet-format/blob/master/Encodings.md and https://arrow.apache.org/docs/python/parquet/parquet_type_handling.html
- Reading a whole file when a query needs three columns: `read_table` and `read_parquet` load every column unless `columns` is passed; a lazy scan or SQL projects for you. https://arrow.apache.org/docs/python/generated/pyarrow.parquet.read_table.html and https://pandas.pydata.org/docs/reference/api/pandas.read_parquet.html and https://docs.pola.rs/user-guide/io/parquet/
- Filtering unsorted data: sorting is what makes min and max ranges tight and non-overlapping, so unsorted row groups are rarely skipped. https://duckdb.org/docs/stable/data/parquet/tips
- Trusting a min or max as a real value: it may be a truncated bound, a missing null count is not zero, and NaN must be assumed present unless counted. https://github.com/apache/parquet-format/blob/master/src/main/thrift/parquet.thrift
- Leaving the codec to the library: the same data comes out uncompressed from one writer and zstd from another. https://docs.rs/parquet/latest/parquet/file/properties/struct.WriterPropertiesBuilder.html and https://docs.pola.rs/api/python/stable/reference/api/polars.DataFrame.write_parquet.html
- The `LZ4` codec is deprecated and not interoperable; `LZ4_RAW` replaces it but is less widely supported than zstd. https://parquet.apache.org/docs/file-format/data-pages/compression/ and https://docs.rs/parquet/latest/parquet/basic/enum.Compression.html
- Gzip costs decompression time on every read. https://duckdb.org/docs/stable/guides/performance/file_formats
- Newer format features are not read everywhere: files at PyArrow's default version 2.6 may not open in every implementation. https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html and https://parquet.apache.org/docs/file-format/implementationstatus/
- A crash before the footer is written leaves a file no reader can open. https://parquet.apache.org/docs/file-format/data-pages/errorrecovery/
- Legacy writers leave strings unmarked, so they load as binary; old list layouts need reader compatibility rules. https://duckdb.org/docs/stable/data/parquet/overview and https://github.com/apache/parquet-format/blob/master/LogicalTypes.md
- A partition key that is also a column inside the files breaks BigQuery's hive detection, as do keys in a different order. https://cloud.google.com/bigquery/docs/hive-partitioned-queries and https://cloud.google.com/bigquery/docs/hive-partitioned-loads-gcs
- An external table is read-only and gives no consistency guarantee if files change under a running query. https://cloud.google.com/bigquery/docs/external-tables
- GeoParquet: an absent `crs` means `OGC:CRS84`, while `null` means unknown; coordinates are always x then y even when the reference system says latitude first. https://geoparquet.org/releases/v2.0.0/
- GeoParquet: a bbox covering does not work for geometries that cross the antimeridian, and BigQuery external tables ignore it. https://geoparquet.org/releases/v2.0.0/ and https://cloud.google.com/bigquery/docs/geospatial-data
- GeoParquet: `.geoparquet` is not the extension; use `.parquet`. https://geoparquet.org/releases/v2.0.0/
- An untrusted path given to `read_parquet` can read local files or fetch remote URLs. https://duckdb.org/docs/stable/operations_manual/securing_duckdb/overview
- Page checksums exist but are neither written nor verified by default in PyArrow. https://arrow.apache.org/docs/python/generated/pyarrow.parquet.write_table.html and https://arrow.apache.org/docs/python/generated/pyarrow.parquet.read_table.html
