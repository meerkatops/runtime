# Decide at the start

What a new Rust repo settles before its first file. Each answer goes in the files of [assets](../assets/README.md), so a builder never has to choose, and nobody discovers crates after the code is written. Each line names the page that says why.

| Decision | Our answer | Page |
|---|---|---|
| Workspace | A virtual root `[workspace]` with `members = ["crates/*"]` and `resolver = "3"`; one `Cargo.lock`, one `target/` | https://doc.rust-lang.org/cargo/reference/workspaces.html and https://doc.rust-lang.org/book/ch14-03-cargo-workspaces.html |
| Crates | One library crate per layer; a thin binary crate whose `main` parses arguments, calls `run`, and reports its error; a `crate-type = ["cdylib", "rlib"]` wrapper for the browser; a crate with only `src/main.rs` exposes no function an integration test can `use`, so such a test can only run the built binary, and the logic lives in a library crate | https://doc.rust-lang.org/book/ch07-01-packages-and-crates.html, https://doc.rust-lang.org/book/ch12-03-improving-error-handling-and-modularity.html, https://doc.rust-lang.org/book/ch11-03-test-organization.html, https://doc.rust-lang.org/cargo/reference/cargo-targets.html |
| Inheritance | `[workspace.package]`, `[workspace.dependencies]`, `[workspace.lints]`; each member declares its path dependencies | https://doc.rust-lang.org/cargo/reference/workspaces.html |
| Edition | `edition = "2024"` in every manifest, since a missing field means the first edition | https://doc.rust-lang.org/cargo/reference/manifest.html and https://doc.rust-lang.org/edition-guide/ |
| Toolchain floor | `rust-version` set, with a stated policy; resolver 3 prefers dependency versions that honor it and falls back to one that does not when no other matches, so the check is the build on the pinned toolchain, which is that floor | https://doc.rust-lang.org/cargo/reference/rust-version.html and https://doc.rust-lang.org/cargo/reference/resolver.html |
| Errors | Library: one `enum Error` per crate implementing `std::error::Error + Send + Sync`, with `From` for each wrapped cause; binary: `main` returns `Result<(), Box<dyn Error>>`; the error crates are third party and the book shows the standard way | https://rust-lang.github.io/api-guidelines/interoperability.html, https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html, https://doc.rust-lang.org/std/error/trait.Error.html |
| Features | Additive only; optional dependencies as `dep:`; a `std` feature that adds std, never a `no_std` feature | https://doc.rust-lang.org/cargo/reference/features.html |
| `no_std` | Only a named reusable kernel (a codec, a tokenizer) with no I/O, when a real target (a wasm viewer, an embedded board) needs it: `#![cfg_attr(not(feature = "std"), no_std)]` with `alloc`, and `ci/check.sh` runs `cargo check -p <crate> --no-default-features`; the root, store, parsers and adapters stay `std`, and no workspace migrates | https://docs.rust-embedded.org/book/intro/no-std.html and https://rustwasm.github.io/docs/book/reference/which-crates-work-with-wasm.html |
| Async | None in a kernel; a runtime only in the entry crate at the I/O edge: `ci/check-lib-imports.sh` refuses tokio, async-std or smol under a lib or core crate, and review holds the other layers; CPU-bound work on `available_parallelism()` threads | https://doc.rust-lang.org/book/ch17-01-futures-and-syntax.html and https://doc.rust-lang.org/book/ch17-06-futures-tasks-threads.html |
| Targets | `wasm32-unknown-unknown` beside native where a repo has a browser crate: no filesystem, no threads, panics abort; that repo's `ci/check.sh` runs `cargo check --target wasm32-unknown-unknown`, a difference its MAP.md names | https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html and https://rustwasm.github.io/docs/book/reference/add-wasm-support-to-crate.html |
| Lock file | Committed; a build after `cargo update` runs on a developer machine before each release as the canary, never per push and never in CI | https://doc.rust-lang.org/cargo/guide/cargo-toml-vs-cargo-lock.html and https://doc.rust-lang.org/cargo/guide/continuous-integration.html |
| Locked | Every cargo call in a script or CI runs `--locked`, so a `Cargo.lock` that no longer matches the manifests fails instead of changing; `ci/check.sh` runs fmt `--check`, clippy `-D warnings`, test and `cargo deny --locked check` | https://doc.rust-lang.org/cargo/commands/cargo-build.html and https://embarkstudios.github.io/cargo-deny/cli/common.html |
| Lints | `[workspace.lints]`: `unsafe_code = "deny"`, `missing_docs` warn, `clippy::pedantic` warn at priority -1; deny `unwrap_used`, `expect_used`, `indexing_slicing`, `panic`, `todo`, `unimplemented`, `unreachable`, `string_slice`, `exit`, `mem_forget`, `print_stdout`, `print_stderr`, `dbg_macro`; `clippy.toml` sets the thresholds and lets tests unwrap, index and print; `rustfmt.toml` with `style_edition = "2024"`; `cargo fmt --all -- --check` in CI | https://doc.rust-lang.org/clippy/, https://doc.rust-lang.org/cargo/reference/manifest.html, https://github.com/rust-lang/rustfmt |
| Docs | `//!` per crate, `///` per public item with Examples, Errors and Panics; `#![warn(missing_docs)]` | https://doc.rust-lang.org/book/ch14-02-publishing-to-crates-io.html and https://doc.rust-lang.org/rustdoc/lints.html |
| Release profile | `lto = true`, `codegen-units = 1`, `panic = "abort"`, `debug = "line-tables-only"` and `strip = "none"`, so a crash backtrace carries file and line; `overflow-checks = true` (a proven kernel opts out with `[profile.release.package.<kernel>] overflow-checks = false` and a measured reason, never a parser of outside bytes); `[profile.bench] inherits = "release"`; measure `opt-level` | https://doc.rust-lang.org/cargo/reference/profiles.html and https://nnethercote.github.io/perf-book/build-configuration.html |
| Toolchain file | `rust-toolchain.toml` pins `channel = "1.99.1"` with `clippy` and `rustfmt`, since clippy's lints change by version and `-D warnings` must judge alike everywhere; `rust-version` is the channel's minor (`"1.99"`): the floor is what we build, so one number moves and nothing checks a second one; a crate we publish adds an MSRV check that day. Nightly is never the build toolchain: its one rule is in [rules](rules.md), under Close to the machine | https://rust-lang.github.io/rustup/overrides.html and https://doc.rust-lang.org/cargo/reference/rust-version.html |
| Dependency audit | `deny.toml`: advisories with yanked denied and `unsound = "all"`, the permissive license list, wildcards denied, unknown registries and git sources denied, with `allow-org` naming only the repo's own GitHub organization | https://embarkstudios.github.io/cargo-deny/checks/advisories/cfg.html and https://embarkstudios.github.io/cargo-deny/checks/sources/cfg.html |
| Unsafe | Workspace `unsafe_code = "deny"`. Which crate may allow it, and how it is listed in MAP.md `## Unsafe crates` and marked at its root, is coding-rulebook R12; its proof (Miri where it has no FFI, a sanitizer fuzz target and a differential test where it has) is in [rules](rules.md), under Close to the machine; standard-check reads the list and refuses any other crate-level lint relaxation | https://doc.rust-lang.org/rustc/lints/levels.html, https://doc.rust-lang.org/nomicon/working-with-unsafe.html, https://github.com/rust-lang/miri |
| Unsafe audit | `cargo geiger` where the repo has `ci/geiger-baseline.txt`: a crate using `unsafe` and missing from the baseline fails, and the baseline changes only in a reviewed change; every other repo runs `cargo deny check` and keeps the Unsafe list above | https://github.com/geiger-rs/cargo-geiger |
| Benchmarks | A kernel crate has `benches/` with `harness = false` and criterion; `[profile.bench]` inherits release; its budget, baseline and measured A/A noise floor live in `ci/proof/bench-<kernel>.sh`, run on a developer machine before a release, never per push; a breach blocks only when it reproduces on a second run and the budget is at least 3x the noise floor | https://bheisler.github.io/criterion.rs/book/faq.html, https://doc.rust-lang.org/cargo/commands/cargo-bench.html and https://doc.rust-lang.org/cargo/reference/profiles.html |
| Fuzzing | A crate parsing outside bytes has a `fuzz/` crate with one `fuzz_target!` per entry function, corpus and crash artifacts checked in, run `cargo +nightly-<date> fuzz run` for a set number of minutes before a release; every parser takes its limits as named values | https://rust-fuzz.github.io/book/cargo-fuzz/setup.html |
| Layers and names | root (bin) `<product>`, app `<product>-app`, adapters `<product>-adapters`, core `<product>-core` (no I/O), lib `lib-<capability>`; imports point down; a lib crate imports no product crate, enforced by `ci/check-lib-imports.sh` from cargo's own graph | https://doc.rust-lang.org/cargo/reference/workspaces.html, https://doc.rust-lang.org/book/ch07-01-packages-and-crates.html, https://rust-lang.github.io/api-guidelines/naming.html |
| Answer contract | One `answer` module is the only writer, held by the `print_stdout` and `print_stderr` lints; with `--json`, stdout holds exactly one JSON value; a bare array keeps its shape; the human footer goes to stderr. Optional, only for a binary shipped as a Claude Code plugin: object answers and failure JSON carry `version`, and `newer` when a higher plugin version is in the cache, tested by `tests/plugin_version.rs` | https://doc.rust-lang.org/book/ch12-06-writing-to-stderr-instead-of-stdout.html and https://rust-lang.github.io/rust-clippy/master/index.html |
| Test fixtures | A temp folder per test, never a real checkout or the real HOME; a test that runs a child builds its env from nothing (`env_clear`, then only PATH and what the child needs), so no variable from the outer run reaches it; a test that runs git also gives it a fixture HOME and `GIT_CONFIG_NOSYSTEM`, so no user or system config is read; one `find_on_path(tool)` prints `SKIPPED: <tool> not on PATH` and never panics | https://doc.rust-lang.org/std/process/struct.Command.html, https://git-scm.com/docs/git, https://git-scm.com/docs/git-config |
| Secret scan | The gitleaks CLI's built-in rules at the installed version (no config file is vendored), `--ignore-gitleaks-allow` and `--log-level error`, any stderr a scanner failure; the working tree is git's file list, never build output; history and range scans with `--log-opts=--no-textconv --no-ext-diff --diff-merges=separate`, so a secret that exists only in a merge is seen; an empty range is clean; the gate fails closed when the scanner cannot run | https://github.com/gitleaks/gitleaks and https://git-scm.com/docs/git-log |
| Private git dependencies | A git dependency is always pinned to a `rev`; where its repo is private, `CARGO_NET_GIT_FETCH_WITH_CLI=true` (`net.git-fetch-with-cli`) makes Cargo fetch with the `git` executable, which uses the credentials git already has | https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html and https://doc.rust-lang.org/cargo/reference/config.html |
| Platforms | The starting files target macOS arm64 (`aarch64-apple-darwin`, tier 1), macOS x64 (`x86_64-apple-darwin`, tier 2 with host tools) and, in `ci.yml`, Linux x64 (`x86_64-unknown-linux-gnu`, tier 1). Windows is not supported: the `ci/` scripts are POSIX sh, and the crash record sets its file mode only on Unix | https://doc.rust-lang.org/rustc/platform-support.html |

## WebAssembly

- `wasm-bindgen` exports functions and structs, imports JavaScript, and writes the TypeScript declarations; the original rustwasm organization is archived and the project lives at its own home. https://wasm-bindgen.github.io/wasm-bindgen/ and https://blog.rust-lang.org/inside-rust/2025/07/21/sunsetting-the-rustwasm-github-org/
- Small integers and floats cross as `number`; 64-bit integers as `BigInt`. https://wasm-bindgen.github.io/wasm-bindgen/reference/types/numbers.html
- A `&[f64]` argument is copied into wasm memory from a typed array; a returned `Box<[f64]>` is copied out to a `Float64Array`; design a frame evaluator to take and return slices once per frame, not per shape. https://wasm-bindgen.github.io/wasm-bindgen/reference/types/number-slices.html and https://wasm-bindgen.github.io/wasm-bindgen/reference/types/boxed-number-slices.html
- An exported struct is a JavaScript class around a pointer; passing it by value moves it and invalidates the JavaScript object. https://wasm-bindgen.github.io/wasm-bindgen/reference/types/exported-rust-types.html
- `Err` throws and `None` is `undefined`. https://wasm-bindgen.github.io/wasm-bindgen/reference/types/result.html
- A panic in wasm is `RuntimeError: unreachable`; install the panic hook in development. https://rustwasm.github.io/docs/book/reference/debugging.html
- Size: `lto`, `opt-level = "s"` or `"z"` measured, `wasm-opt`, no `format!` on the hot path. https://rustwasm.github.io/docs/book/reference/code-size.html
