# The coding rulebook: Python

Read `shared.md` first: it holds the Concepts (C), the rules for all languages (A) and for agents (G), the review bar (B) and the talks cited here by short name. An id starting R is in `rust.md`, one starting T in `typescript.md`, one starting X in `react.md`.

Python's own facts, page by page, are /ground-python's; these are the choices we make with them. The runtime checks no annotation, so the tools below have to.

**P1. Strictly typed, with no `Any` leaking in.** Every function is fully annotated and passes the repo's checker in strict mode: `typeCheckingMode = "strict"` for pyright, `strict = true` for mypy. An untyped import is a finding, not something to silence. A parameter that accepts anything is `object`, not `Any` (ruff ANN401). Source: https://docs.python.org/3.14/library/typing.html ("The Python runtime does not enforce function and variable type annotations"); https://microsoft.github.io/pyright/configuration.md (strict makes `reportUnknown*` errors); https://mypy.readthedocs.io/en/stable/command_line.html; https://typing.python.org/en/latest/reference/best_practices.html.

**P2. Check after every edit.** After each edit the builder runs the per-edit checks on the files it touched: the tool gate's steps 1 to 3 (ruff format, ruff check, the type checker), reading the full diagnostics, as JSON where the tool offers it, not a summary. The whole gate, with pytest, runs once the change is clean and again before the builder returns. Source: arXiv 2508.00422 (a generate, check and repair loop driven by mypy brought LLM annotations to about 88.6% mypy-clean); arXiv 2507.18755 (an agent's solve rate went from 28.5% to 42.3% with static analysis and test feedback; not Python-specific); https://microsoft.github.io/pyright/command-line.md (`--outputjson`).

**P3. Parse at the boundary.** Outside input (JSON, env, CLI, HTTP, files) is checked once at the edge and turned into a `@dataclass(frozen=True)` or a checked `TypedDict`. A failure raises an error that carries the bad input. The core never takes a `dict[str, Any]` or a raw `dict`. Source: https://docs.python.org/3.14/library/typing.html ("At runtime 'TypedDict instances' are simply dicts"); https://docs.python.org/3.14/library/dataclasses.html.

**P4. Catch narrowly, never swallow.** Each `except` names the types it handles. No bare `except:`, and no `except Exception:` followed by `pass`, `continue` or a default. A broad catch is allowed only at the process edge that writes the crash record (A6). Ruff E722, BLE001 and S110 enforce it. Source: https://peps.python.org/pep-0008/ ("can disguise other problems"); https://docs.astral.sh/ruff/rules/blind-except/; https://docs.astral.sh/ruff/rules/try-except-pass/.

**P5. Raise from the cause.** Inside an `except`, re-raise as `raise NewError(...) from err`; `from None` only to hide the cause on purpose, with a comment saying why. The new error names its inputs (A4), or `add_note()` adds them. Ruff B904 enforces it. Source: https://docs.python.org/3.14/tutorial/errors.html (Exception Chaining); https://docs.astral.sh/ruff/rules/raise-without-from-inside-except/.

**P6. Importing a module does nothing.** Module level only defines things and sets constants: no I/O, network, env read, logging setup or thread start at import. The entry point runs under `if __name__ == "__main__":` or as a `[project.scripts]` function. Source: https://docs.python.org/3.14/library/__main__.html ("the script code would unintentionally execute as well").

**P7. Every resource opened in a `with`.** Files, sockets, locks, temp dirs, subprocess pipes and clients are opened in a `with` or `async with`, never a bare `open()` with a hand-written `close()`. Ruff SIM115 enforces it. Source: https://docs.python.org/3.14/tutorial/errors.html (Predefined Clean-up Actions); https://docs.astral.sh/ruff/rules/open-file-with-context-handler/.

**P8. asyncio discipline.** Tasks run under `asyncio.TaskGroup`; a bare `create_task` with no kept reference is a finding (RUF006). An `async def` makes no blocking call (no `time.sleep`, sync HTTP or CPU-heavy work; ASYNC210, ASYNC251); blocking work goes through `asyncio.to_thread`. Source: https://docs.python.org/3.14/library/asyncio-task.html (the loop keeps "weak references to tasks"); https://docs.python.org/3.14/library/asyncio-dev.html ("Blocking (CPU-bound) code should not be called directly"); https://docs.astral.sh/ruff/rules/blocking-sleep-in-async-function/.

**P9. Subprocess takes a list, never a shell.** Call `subprocess.run([...], check=True)` with an argument list; `shell=True` is a finding (ruff S602). A non-zero exit raises; it is never ignored. Source: https://docs.python.org/3.14/library/subprocess.html (Security Considerations); https://docs.astral.sh/ruff/rules/subprocess-popen-with-shell-equals-true/.

**P10. Every import resolves and every dependency is declared.** A new third-party import is listed under `[project] dependencies` and resolves for the type checker; the checker does not set `ignore_missing_imports`. Source: https://mypy.readthedocs.io/en/stable/running_mypy.html (an unresolved module is treated as `Any`; "We recommend avoiding --ignore-missing-imports"); arXiv 2406.10279 (at least 5.2% of packages commercial models recommend do not exist, 21.7% for open models).

**P11. A hot loop is measured with cProfile and timeit.** A performance change names `python -m cProfile -o out.prof` for where the time goes and `timeit` for its before and after numbers (A1). Source: https://docs.python.org/3.14/library/profile.html ("cProfile is recommended for most users").

**P12. The shared rules, in Python.** A3: no `global` statement (PLW0603), no mutable default argument (B006; use `field(default_factory=…)`), no module-level `dict` or `list` written after import; context is passed as an argument. A4: no `.get(key, 0)`, `or ""` or `or []` standing in for missing data. G1: a `Protocol` or ABC needs two real implementations; no metaclass and no decorator that hides control flow. G3: public functions take `collections.abc` types and return concrete ones. G6: prefer a ruff rule selected in `pyproject.toml` to prose. Source: https://docs.astral.sh/ruff/rules/global-statement/, https://docs.astral.sh/ruff/rules/mutable-argument-default/, https://docs.python.org/3.14/tutorial/controlflow.html ("The default value is evaluated only once"), https://typing.python.org/en/latest/reference/best_practices.html, https://docs.astral.sh/ruff/linter/.

Rules P13 to P24 apply to data, machine learning and model inference work.

**P13. Models are pinned by commit and loaded offline from one directory.** A model is fetched by one named fetch step, at a full commit hash listed in a checked-in manifest, into the model directory config names. Run-time code loads from that path with `local_files_only=True`, under `HF_HUB_OFFLINE=1` and `HF_HUB_DISABLE_TELEMETRY=1`, and never passes a bare repo id. A model missing from the directory is an error that names it (A4), never a download. Source: https://huggingface.co/docs/huggingface_hub/guides/download; https://huggingface.co/docs/transformers/installation; https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables.

**P14. Safetensors only; no pickle from outside; no remote code unread.** Weights load from safetensors, with `use_safetensors=True`. `pickle.load`, `joblib.load` and `torch.load` open only files this repo wrote, and `torch.load` keeps `weights_only=True`. `trust_remote_code=True` is a finding unless the repo's code was read at the pinned commit (P13) and a comment beside the call says who read it. Ruff S301 flags the pickle calls. Source: https://docs.python.org/3/library/pickle.html; https://docs.pytorch.org/docs/stable/notes/serialization.html; https://huggingface.co/docs/transformers/models; https://scikit-learn.org/stable/model_persistence.html; https://docs.astral.sh/ruff/rules/suspicious-pickle-usage/.

**P15. One seed, set at the entry point and recorded.** The seed comes from config. The entry point seeds `random` and `torch` with it and builds one `np.random.default_rng(seed)` that is passed as an argument (A3); no `np.random.*` module-level call (ruff NPY002). Every scikit-learn splitter and estimator gets an integer `random_state`. Tests and evaluations run with `torch.use_deterministic_algorithms(True)`. The seed is written with the result (P19). Source: https://docs.pytorch.org/docs/stable/notes/randomness.html; https://numpy.org/doc/stable/reference/random/index.html; https://scikit-learn.org/stable/common_pitfalls.html; https://docs.astral.sh/ruff/rules/numpy-legacy-random/.

**P16. Vectorize; never loop rows.** Work on a frame or array is a column expression or an array operation. `iterrows`, `itertuples`, `apply(axis=1)`, `map_elements` and a `for` over rows are findings; one is allowed only where no vectorized form exists, with a comment saying so and P11's numbers. Source: https://numpy.org/doc/stable/user/whatisnumpy.html; https://pandas.pydata.org/docs/user_guide/basics.html; https://docs.pola.rs/user-guide/expressions/user-defined-python-functions/.

**P17. A frame is typed at the boundary.** P3 for tables: the function that reads a file or query names every column it keeps and its dtype, checks them once, and raises on a missing column or a failed cast, naming the file and column (A4). No dtype is left to inference, and no column is dropped or filled silently. The core takes that typed frame, or a frozen dataclass for a single record; float width is chosen there, once. Large tables are Parquet read lazily; what Parquet does, and what a project settles before it writes its first Parquet file, are the `runtime-engineering:ground-parquet` skill's. Assignment into a pandas frame uses `.loc`. Source: https://pandas.pydata.org/docs/user_guide/scale.html; https://docs.pola.rs/user-guide/concepts/lazy-api/; https://pandas.pydata.org/docs/user_guide/indexing.html.

**P18. Device and dtype come from config, not code.** One function at the entry point turns the configured device and dtype into a `torch.device` and a `torch.dtype`, and both are passed down (A3). No `.cuda()`, no `"cuda"` or `"mps"` literal and no `is_available()` branch below it. A configured device that is absent raises (A4); the code never falls back to CPU on its own, and never leaves `device` unset for a library to choose. Source: https://docs.pytorch.org/docs/stable/notes/cuda.html; https://docs.pytorch.org/docs/stable/notes/mps.html; https://huggingface.co/docs/transformers/main_classes/pipelines.

**P19. Every result records what produced it.** A metric, prediction file, embedding index or exported model is written with a record beside it (G5): each model's repo id and commit hash, each input data file's path and content hash, the seed, the device and dtype, the code's git commit and the lockfile's hash. A result with no record is not reported. Source: https://docs.pytorch.org/docs/stable/notes/randomness.html; https://huggingface.co/docs/huggingface_hub/guides/download; https://packaging.python.org/en/latest/specifications/pylock-toml/.

**P20. Inference is explicit.** Inference code calls `model.eval()` and runs under `torch.inference_mode()`. The tokenizer loads from the same directory and commit as its model (P13). Batch size comes from config and is measured (P11), not guessed. Every tokenizer call sets `padding` and `truncation`; every `generate()` call sets `max_new_tokens`; a multilingual translation model's target language is an argument, never a default. Source: https://docs.pytorch.org/docs/stable/generated/torch.autograd.grad_mode.inference_mode.html; https://huggingface.co/docs/transformers/main/en/preprocessing; https://huggingface.co/docs/transformers/llm_tutorial; https://huggingface.co/docs/transformers/main_classes/pipelines; https://huggingface.co/docs/transformers/model_doc/marian.

**P21. Split first; fit inside a Pipeline; touch the test set once.** The split is the first step after loading and is made by a function that takes the seed. Every fitted preprocessing step lives in a scikit-learn `Pipeline` with its estimator; a bare `fit_transform` on a full dataset is a finding. Choices are made on validation folds, and the test set is scored once, for the reported number. Source: https://scikit-learn.org/stable/common_pitfalls.html; https://scikit-learn.org/stable/modules/cross_validation.html.

**P22. One embedding space per index, written down.** An index stores, with its vectors, the model's repo id and commit, the dimension, whether vectors are normalized and the similarity function (P19). Vectors are L2-normalized once, at write, and scored by dot product. A query is encoded by the same pinned model, and a query against an index whose record differs raises. Encoding is batched; search is exact until P11's numbers show it too slow. Source: https://scikit-learn.org/stable/modules/metrics.html; https://sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html; https://sbert.net/examples/sentence_transformer/applications/semantic-search/README.html.

**P23. A served model is an exported file, checked against its source.** Serving loads an ONNX file with ONNX Runtime, its `providers` list from config (P18), and imports no training code. The export step compares the exported model's outputs with the source model's on fixed inputs, within a stated tolerance, and fails when they differ; the tolerance and inputs go in the record (P19). Source: https://docs.pytorch.org/docs/stable/onnx.html; https://huggingface.co/docs/optimum-onnx/onnx/usage_guides/export_a_model; https://onnxruntime.ai/docs/api/python/api_summary.html.

**P24. A notebook only calls.** A notebook imports the installed package and calls it; it defines no function or class that anything else uses, and nothing imports from a notebook. Logic found in a notebook moves to a module with a test (A5). Notebooks are committed with outputs cleared. Source: https://docs.python.org/3/tutorial/modules.html; https://nbformat.readthedocs.io/en/latest/format_description.html.

## Crash record in Python (A6)

The entry point installs these before any work: `sys.excepthook` for an uncaught exception on the main thread (not called for `SystemExit`; an exception out of `asyncio.run(main())` reaches it too); `threading.excepthook` for one in `Thread.run()`; `loop.set_exception_handler` for errors in callbacks and tasks whose exception nobody retrieved; and `faulthandler.enable(file=f)` for a segfault, abort or fatal error, with `f` kept open for the life of the process (that dump is minimal, since it cannot allocate). Each hook writes the record, flushes it, then exits non-zero. Do not count on `atexit`: it does not run on an unhandled signal, a fatal error or `os._exit()`. Source: https://docs.python.org/3.14/library/sys.html, https://docs.python.org/3.14/library/threading.html, https://docs.python.org/3.14/library/asyncio-eventloop.html, https://docs.python.org/3.14/library/faulthandler.html, https://docs.python.org/3.14/library/atexit.html.

## Tool gate in Python

Run in order before any model review; any non-zero exit stops the gate, and the builder fixes what it names (P2). In a repo that predates this rulebook, its own CI command is the gate instead (`shared.md`, Existing repos):

1. `ruff format --check`. https://docs.astral.sh/ruff/formatter/
2. `ruff check --output-format json`, its rule set from `pyproject.toml`. https://docs.astral.sh/ruff/linter/
3. `pyright --outputjson` with `typeCheckingMode = "strict"`, or `mypy --strict` when the repo already configures mypy. A new repo uses pyright: its strict mode makes unknown types errors (`reportUnknown*`), which catches `Any` leaking in from an untyped import. https://microsoft.github.io/pyright/configuration.md, https://mypy.readthedocs.io/en/stable/command_line.html
4. `pytest --strict`; exit 5, no tests collected, fails the gate. https://docs.pytest.org/en/stable/reference/reference.html, https://docs.pytest.org/en/stable/reference/exit-codes.html

## Shared library home in Python

A piece two Python repos need lives in one shared package your organization names; where none exists yet, raise it with the repo's owner before copying it (G2, C4). Starter files are /ground-python's assets.
