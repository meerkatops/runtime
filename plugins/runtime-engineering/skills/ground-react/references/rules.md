# How a React front end behaves

Each fact names the page that states it. Read the page before relying on the fact in a review. The choices we make on top of these pages are the X rules in the coding-rulebook skill in this plugin (`runtime-engineering:coding-rulebook`, `references/react.md`); check front-end work against them too. React code is TypeScript, so the language's facts are in the ground-typescript skill.

## React

- A component and a Hook are pure: the same props, state and context give the same output, side effects run outside render, and props, state and values passed to JSX or to a Hook are never mutated. https://react.dev/reference/rules
- Hooks are called only at the top level of a function component or a custom Hook: not in a loop, a condition, a nested function, an event handler, a `try`/`catch`/`finally` block or after an early return. https://react.dev/reference/rules/rules-of-hooks
- An Effect synchronizes a component with a system outside React. Transforming data for rendering and handling a user event need none: compute during render and do the work in the event handler. https://react.dev/learn/you-might-not-need-an-effect
- A value that can be computed from props or state is not state; a prop is not mirrored into state. https://react.dev/learn/choosing-the-state-structure
- State two components share moves to their closest common parent and comes down as props. https://react.dev/learn/sharing-state-between-components
- A `key` is unique among siblings and does not change. The array index as a key causes bugs when items reorder, and a key made during render recreates every item on every render. Giving a component a different `key` resets its state. https://react.dev/learn/rendering-lists and https://react.dev/learn/you-might-not-need-an-effect
- `useActionState(action, initialState)` returns the state, a dispatch function and an `isPending` flag; calls are queued and run in order, each receiving the previous result. https://react.dev/reference/react/useActionState
- `<Suspense>` shows its fallback while a child loads lazy code or reads a promise with `use`; it does not detect data fetched in an Effect or an event handler. https://react.dev/reference/react/Suspense
- An error boundary is a class component with `getDerivedStateFromError`; there is no way to write one as a function component. https://react.dev/reference/react/Component
- `createRoot` takes `onUncaughtError`, `onCaughtError` and `onRecoverableError`, each called with the error and its `componentStack`. https://react.dev/reference/react-dom/client/createRoot
- `dangerouslySetInnerHTML` writes raw HTML into the DOM; with markup from anywhere but a completely trusted source it is an XSS hole. The `style` attribute is recommended only for styles that depend on JavaScript variables. https://react.dev/reference/react-dom/components/common
- The React Compiler is stable. It memoizes components and values at build time and skips a component that breaks the Rules of React; `useMemo` and `useCallback` remain as an escape hatch. https://react.dev/learn/react-compiler/introduction
- The `recommended` set of `eslint-plugin-react-hooks` holds `rules-of-hooks`, `exhaustive-deps` and the compiler's diagnostics, among them `purity`, `immutability`, `refs`, `set-state-in-effect` and `set-state-in-render`. https://react.dev/reference/eslint-plugin-react-hooks
- React recommends starting a new app with a framework and names Next.js's App Router first; building from scratch starts with a build tool such as Vite. https://react.dev/learn/creating-a-react-app and https://react.dev/learn/build-a-react-app-from-scratch

## Server and Client Components

- In the App Router, layouts and pages are Server Components by default. https://nextjs.org/docs/app/getting-started/server-and-client-components
- `"use client"` sits at the very top of a file, above its imports, and marks that module and everything it imports as client code. It draws its boundary on the module dependency tree, not the render tree. https://react.dev/reference/rsc/use-client
- Props passed from a Server Component to a Client Component must be serializable. React context is not supported in Server Components; a provider is a Client Component that accepts `children`. https://nextjs.org/docs/app/getting-started/server-and-client-components
- A Server Function is an async function marked `"use server"`. It is called over the network with POST, its arguments are fully client-controlled, and it is reachable by a direct request, not only through the page. https://nextjs.org/docs/app/getting-started/mutating-data and https://react.dev/reference/rsc/use-server
- Next.js compares a Server Action's `Origin` header with its `Host` (or `X-Forwarded-Host`) and aborts on a mismatch, gives each action an encrypted id, and removes unused actions from the client bundle. The page states no such check for a Route Handler; it lists `route.ts` among the files to audit. https://nextjs.org/docs/app/guides/data-security
- `Sec-Fetch-Site` says whether a request comes from the same origin, the same site, another site or the person (`none`). A page cannot set it, and a browser sends it only to a potentially trustworthy URL. https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Site
- A form whose `action` is a Server Action submits before JavaScript has loaded. https://nextjs.org/docs/app/getting-started/mutating-data

## Next.js: data, caching and routes

- Next.js 16 needs Node.js 20.9 or later and TypeScript 5.1 or later. Turbopack is the default bundler for `next dev` and `next build`, `middleware` is renamed `proxy`, and `params`, `searchParams`, `cookies()` and `headers()` are read only with `await`. https://nextjs.org/docs/app/guides/upgrading/version-16
- `fetch` in a Server Component is not cached by default and blocks rendering until it completes; identical `fetch` calls in one render are memoized. https://nextjs.org/docs/app/getting-started/fetching-data
- With `cacheComponents: true`, `"use cache"` caches the return value of an async function or component, `cacheLife` names how long, and an uncached read outside `<Suspense>` is reported as a blocking route. `create-next-app`'s recommended defaults turn Cache Components on, with `partialPrefetching`. https://nextjs.org/docs/app/getting-started/caching
- Prerendering is not caching. At build time Next.js renders each route into a static shell: a `"use cache"` result is included unless its lifetime is too short, a `<Suspense>` fallback is included while its content streams at request time, and module imports, `fs.readFileSync` and pure computations complete during the prerender and are included with no directive. `<Suspense>` does not opt a component into request-time rendering: synchronous work completes during the prerender whether or not it is wrapped. https://nextjs.org/docs/app/getting-started/caching
- `await connection()` makes rendering wait for a request: the code after it runs at request time only. A query through a synchronous database driver completes during the prerender unless `connection()` or a request-time API comes before it. https://nextjs.org/docs/app/api-reference/functions/connection
- Of `cacheLife`'s presets, only `seconds` is excluded from the prerender: a cache with `revalidate` of 0 or `expire` under 5 minutes becomes a hole filled at request time. https://nextjs.org/docs/app/api-reference/functions/cacheLife
- `updateTag` expires a tag's cached data at once, so the caller reads its own write; it can be called only in a Server Action. `revalidateTag` serves the stale entry while a fresh one loads. https://nextjs.org/docs/app/getting-started/revalidating
- Cookies and headers are read outside a cached scope and passed in as arguments, which become part of the cache key. https://nextjs.org/docs/app/api-reference/directives/use-cache
- A Route Handler is a `route.ts` file exporting functions named for HTTP methods. It is not cached by default, and it cannot share a route segment with `page.tsx`. https://nextjs.org/docs/app/getting-started/route-handlers
- A Content Security Policy with a nonce is set in `proxy.ts` and needs every page rendered for its request; Partial Prerendering is incompatible with it. Without a nonce, the header is set in the Next config's `headers()`, with `'unsafe-inline'` for `script-src` and `style-src`; `'unsafe-eval'` is needed in development only. Hash-based integrity (`experimental.sri`) is experimental. https://nextjs.org/docs/app/guides/content-security-policy
- `import "server-only"` at the top of a module makes the build fail when client code imports it. https://nextjs.org/docs/app/guides/data-security
- `proxy.ts`, one per project, runs before a request completes. It is not meant for slow data fetching or as the whole of session management or authorization. https://nextjs.org/docs/app/getting-started/proxy
- A variable is inlined into the browser bundle at build time only when its name starts with `NEXT_PUBLIC_` and it is read as `process.env.NAME`; a dynamic lookup is not inlined, and the value is frozen at build. Vite exposes a variable to client code only when it starts with `VITE_`. https://nextjs.org/docs/app/guides/environment-variables and https://vite.dev/guide/env-and-mode
- `metadata` and `generateMetadata` are supported only in Server Components. https://nextjs.org/docs/app/getting-started/metadata-and-og-images
- `next/image` sizes an image for the device and reserves its space so the layout does not shift; a statically imported image's width and height are read for you. `next/font` self-hosts a font, so the browser makes no request to the font's host. https://nextjs.org/docs/app/getting-started/images and https://nextjs.org/docs/app/getting-started/fonts
- `next lint` is gone; ESLint runs from its own CLI with a flat config extending `eslint-config-next/core-web-vitals`, which carries Next's plugin and the recommended sets of the React and React Hooks plugins. It supports ESLint 9 and 10, though some of its plugins do not yet list ESLint 10 as a peer. https://nextjs.org/docs/app/api-reference/config/eslint
- `typedRoutes` types every link against the routes that exist; `next typegen` writes the route types without a build. https://nextjs.org/docs/app/api-reference/config/next-config-js/typedRoutes and https://nextjs.org/docs/app/api-reference/config/typescript

## Errors

- An expected error (a failed validation, a refused request) is returned as a value and shown through `useActionState`; an uncaught exception is thrown and caught by an error boundary. https://nextjs.org/docs/app/getting-started/error-handling
- `error.tsx` is a Client Component that receives `error` and `retry`; `retry` became stable in 16.3. It wraps its segment's page and nested layouts, not the layout beside it. `global-error.tsx` handles the root layout, renders its own `<html>` and `<body>`, and gets none of the app's global styles. https://nextjs.org/docs/app/api-reference/file-conventions/error
- In production an error from a Server Component reaches the browser with a generic message and a `digest` that matches the server's log. https://nextjs.org/docs/app/api-reference/file-conventions/error
- `instrumentation.ts`, in the project root or `src`, exports `register`, called once when a server instance starts in every runtime, and `onRequestError`, called with the error, the request (`path`, `method`, `headers`) and its context. `instrumentation-client.ts` runs in the browser before the app becomes interactive. https://nextjs.org/docs/app/api-reference/file-conventions/instrumentation and https://nextjs.org/docs/app/api-reference/file-conventions/instrumentation-client

## CSS

- A custom property is declared with two dashes, obeys the cascade and inherits; declared on `:root` it is available to the whole document. https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties
- `prefers-color-scheme` reports whether the person asked for light or dark, through the operating system or the browser. `color-scheme: light dark` lets the browser draw form controls, scrollbars and the canvas to match. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme and https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme
- Grid is a two-dimensional layout, rows and columns together; flexbox is one-dimensional, a row or a column at a time. https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Basic_concepts and https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Basic_concepts
- A container query styles an element by the size of its container, where a media query uses the viewport. https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries
- `@layer` declares cascade layers and their order of precedence. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@layer
- `prefers-reduced-motion: reduce` matches when the person has asked the device to minimize motion that is not essential. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion
- `navigator.sendBeacon` returns true when the browser queued the data for transfer and false otherwise. https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon
- `:focus-visible` matches when the browser judges that focus should be shown, as it does for keyboard use. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:focus-visible
- A CSS Module scopes its class names to the file by generating unique names. Global styles are not removed on navigation, so they are kept for what is truly global, and the order of CSS follows the order of imports. https://nextjs.org/docs/app/getting-started/css

## Material UI

- The current major is 9; its upgrade guide starts from 7, and no 8 was published. Version 9 removes the APIs deprecated before it, `GridLegacy` among them, and targets Chrome 117, Firefox 121 and Safari 17. https://mui.com/material-ui/migration/upgrade-to-v9/
- Since 7 the packages use the `exports` field, and an import more than one level deep does not resolve. https://mui.com/material-ui/migration/upgrade-to-v7/
- `createTheme({ cssVariables: true })` writes the theme as CSS custom properties (`--mui-palette-primary-main`). With the built-in dark scheme, both schemes are generated under `prefers-color-scheme`, and `theme.vars` refers to the variables. https://mui.com/material-ui/customization/css-theme-variables/usage/
- CSS theme variables prevent the dark-mode flash on a server-rendered page, at the cost of a larger HTML document. https://mui.com/material-ui/customization/css-theme-variables/overview/
- `cssVariables: { nativeColor: true }` makes the theme derive shades with CSS `color-mix` and relative colors in place of JavaScript, so a palette value may be a `var(--…)`; it works only in browsers with relative color syntax. https://mui.com/material-ui/customization/css-theme-variables/native-color/
- The theme's `spacing` is 8 px by default and can be a number, a function or an array; `theme.spacing(2)` multiplies it. The type `SpacingOptions` in @mui/system 9.5.0 also takes a string, and with `cssVariables` a string such as `var(--space-unit)` becomes `--mui-spacing`, multiplied with `calc()` (seen in the starting app's HTML); the page does not list the string form. `shape.borderRadius` is typed `number | string`. https://mui.com/material-ui/customization/spacing/
- Material UI's styles are `<style>` elements that Emotion injects, and some components set inline `style` attributes. Under a Content Security Policy they need a nonce passed to Emotion's cache, or, where no nonce is possible, `'unsafe-inline'`. https://mui.com/material-ui/guides/content-security-policy/
- A manual light and dark switch sets `colorSchemeSelector` to a class or data attribute and adds `InitColorSchemeScript`; `useColorScheme` reads and sets the mode, which is `undefined` on the first render. https://mui.com/material-ui/customization/css-theme-variables/configuration/ and https://mui.com/material-ui/customization/dark-mode/
- In the App Router, `AppRouterCacheProvider` from `@mui/material-nextjs/v<major>-appRouter` collects the styles made during server rendering into `<head>`. Its `enableCssLayer` option wraps them in `@layer mui`, which another styling system needs in order to override them. Passing `next/link` to a `component` prop from a Server Component needs a `"use client"` wrapper. https://mui.com/material-ui/integrations/nextjs/
- `sx` is the best choice for a one-off style on one instance, `styled()` for a reusable component, and the theme's `components` for a global override. https://mui.com/material-ui/customization/how-to-customize/
- Importing from the package root, a barrel import, slows the development server's start and rebuilds; production builds tree-shake either way. https://mui.com/material-ui/guides/minimizing-bundle-size/
- Each component's conformance to WCAG 2.2 A and AA is reported per criterion, with who is responsible for it; page-level criteria are the application's. https://mui.com/material-ui/getting-started/accessibility/
- Using Tailwind CSS 4 beside Material UI needs `enableCssLayer` and a layer order that puts `mui` before `utilities`. https://mui.com/material-ui/integrations/tailwindcss/tailwindcss-v4/

## Accessibility and performance

- The first rule of ARIA use: where a native HTML element or attribute has the semantics and behavior needed, use it, not a repurposed element with a role. https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA
- WCAG 2.2 at level AA asks for text contrast of at least 4.5:1, or 3:1 for large text; 3:1 for the visual edges of controls; content that reflows at 320 CSS px wide without scrolling in two dimensions; pointer targets of at least 24 by 24 CSS px; everything operable by keyboard; and a visible focus indicator. https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html, https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html, https://www.w3.org/WAI/WCAG22/Understanding/reflow.html, https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html, https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html and https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html
- The Core Web Vitals and their good thresholds, at the 75th percentile of page loads: Largest Contentful Paint within 2.5 seconds, Interaction to Next Paint of 200 milliseconds or less, Cumulative Layout Shift of 0.1 or less. https://web.dev/articles/vitals
- `Intl.NumberFormat` with `style: "unit"` formats a number with its unit. https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat

## Testing

- Vitest runs files with `.test.` or `.spec.` in their names, reads `vite.config.*` or its own `vitest.config.*`, uses the `node` environment unless `environment` says `jsdom` or `happy-dom`, and provides no global `test` or `expect` unless `globals` is set. https://vitest.dev/guide/, https://vitest.dev/config/environment and https://vitest.dev/config/globals
- Vitest does not support async Server Components; Next.js recommends end-to-end tests for them. https://nextjs.org/docs/app/guides/testing/vitest
- Testing Library's query priority starts with `getByRole`, then `getByLabelText`; `getByTestId` is last. `userEvent` simulates whole interactions where `fireEvent` dispatches one DOM event. https://testing-library.com/docs/queries/about/ and https://testing-library.com/docs/user-event/intro/
- Playwright's locators wait and retry; it recommends role locators, isolated tests and testing what the user sees. `webServer` starts the app before the tests, and a project can emulate a device or a viewport. With `reuseExistingServer` true, a server already on the port or URL is reused; with it false, Playwright throws when one is listening. https://playwright.dev/docs/best-practices, https://playwright.dev/docs/locators, https://playwright.dev/docs/test-webserver and https://playwright.dev/docs/emulation
- Next.js recommends running Playwright against the production build. https://nextjs.org/docs/app/guides/testing/playwright
- Automated accessibility scans find some problems; many are found only by hand. https://playwright.dev/docs/accessibility-testing
