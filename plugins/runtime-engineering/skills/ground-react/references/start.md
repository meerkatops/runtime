# Decide at the start

What a new front end settles before its first file. Each answer is a setting in `package.json`, `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`, the token file or a named file of the starting app in this skill's assets, so a builder never has to choose. The rule behind an answer is the coding-rulebook's X rule the row names (`references/react.md` in the coding-rulebook skill); the row says only where the answer is set. Each line names the page that says why.

## Traps the pages name

- `"use client"` on a layout or a page pulls everything it imports into the browser bundle. https://nextjs.org/docs/app/getting-started/server-and-client-components
- A Server Function is a public endpoint: a check in the page, the layout or `proxy.ts` does not protect it. https://nextjs.org/docs/app/guides/production-checklist
- A layout that reads uncached or request data blocks navigation, and a `loading.tsx` in the same segment does not cover it. https://nextjs.org/docs/app/getting-started/fetching-data
- A `NEXT_PUBLIC_` value is frozen at build: one build promoted to another environment keeps the first one's values. `process.env[name]` with a computed name is not inlined at all. https://nextjs.org/docs/app/guides/environment-variables
- An error boundary does not catch an error thrown in an event handler or in async code, nor one from the layout beside it. https://nextjs.org/docs/app/getting-started/error-handling and https://nextjs.org/docs/app/api-reference/file-conventions/error
- `global-error.tsx` gets no global stylesheet and no theme, so it is written with plain elements. https://nextjs.org/docs/app/api-reference/file-conventions/error
- `register` runs in every runtime; Node-only code is imported inside it, under `process.env.NEXT_RUNTIME === "nodejs"`. https://nextjs.org/docs/app/guides/instrumentation
- With a custom `webpack` config, `next build` fails in Next.js 16, because Turbopack is the default. https://nextjs.org/docs/app/guides/upgrading/version-16
- Third-party declaration files do not pass a full lib check, so a front end sets `skipLibCheck: true`; the coding-rulebook's X21 allows it there only. Seen with `tsc --skipLibCheck false` on the starting app: @mui/material 9.5.0 fails `exactOptionalPropertyTypes` (TS2430), `.next/types/link.d.ts` from Next.js 16.4.6 names a `JSX` namespace that is not found (TS2503), and Vitest 5.1.0 and @testing-library/jest-dom 7.0.1 declare `Assertion` with different type parameters (TS2428). https://www.typescriptlang.org/tsconfig/#skipLibCheck
- With `allowJs` absent from `tsconfig.json`, `next build` writes `"allowJs": true` into it (seen on Next.js 16.4.6, which prints "allowJs was set to true"); the starting file sets it to `false`, since no JavaScript file is part of the app and none would be type-checked. https://www.typescriptlang.org/tsconfig/#allowJs
- Several plugins inside `eslint-config-next` do not list ESLint 10 as a peer, so `npm install` refuses them beside it; the starting `package.json` names each in `overrides`. https://nextjs.org/docs/app/api-reference/config/eslint and https://docs.npmjs.com/cli/v11/configuring-npm/package-json#overrides
- With Cache Components, a read that can finish at build time is prerendered into the static shell with no `"use cache"`: `fs.readFileSync`, a query through a synchronous database driver, a pure computation. `<Suspense>` does not hold it back; `await connection()` does. https://nextjs.org/docs/app/getting-started/caching and https://nextjs.org/docs/app/api-reference/functions/connection
- A Content Security Policy with a nonce needs every page rendered for its request and is incompatible with Partial Prerendering, so an app with Cache Components sends the policy without one. https://nextjs.org/docs/app/guides/content-security-policy
- Next.js compares `Origin` with `Host` for a Server Function only; a Route Handler that takes a browser's POST makes that check itself. https://nextjs.org/docs/app/guides/data-security
- With `reuseExistingServer` true, Playwright tests whatever already answers on the port, a dev server or an older build included; with it false, an occupied port stops the run. https://playwright.dev/docs/test-webserver
- `navigator.sendBeacon` returns false when the browser did not queue the data; nothing is thrown. https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon
- `import-x/no-cycle` reports nothing in a TypeScript app until `import-x/parsers` and a resolver that knows `.ts` and `.tsx` are set (seen on eslint-plugin-import-x 4.17.1: a planted cycle passed without them). https://github.com/un-ts/eslint-plugin-import-x
- Vitest does not run async Server Components. https://nextjs.org/docs/app/guides/testing/vitest
- With Vitest's `globals` off, Testing Library cannot register its cleanup, so the setup file calls `cleanup` after each test. https://testing-library.com/docs/react-testing-library/setup/
- `useColorScheme`'s `mode` is `undefined` on the first render; reading it without that case causes a hydration mismatch. https://mui.com/material-ui/customization/dark-mode/
- Setting `typography.fontFamily` to a `next/font` variable for Roboto drops Material UI's Roboto letter spacing; add the font's class to `<html>` instead. https://mui.com/material-ui/integrations/nextjs/
- An index used as a key, and state mirrored from a prop, both show stale rows after a reorder or a prop change. https://react.dev/learn/rendering-lists and https://react.dev/learn/choosing-the-state-structure
